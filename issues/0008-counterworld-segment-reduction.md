# [Experiment] 同じ画像に一致する二つの3D候補から，その間の連続な候補を作れるか

> 状態：解析的な問いは決着した．数値検証は計測器の事前検査に通らず無効である．VGGTの学習・推論は実施していない．

## 先に結論

複数画像から一つの3D再構成を返す代わりに，同じ画像を説明する複数の3D候補を返すfeed-forward 3Dを検討した．具体的には，距離の問いへ反対に答える「近い3D」と「遠い3D」を，連続に変形できる区間としてmodelに出させる案である．

しかし，今回定義した球の設定では，連続区間を直接予測する必要はなかった．近い端点と遠い端点があれば，中心位置と半径を同じ割合で補間するだけで，その間の全候補を作れる．逆に，区間内の任意の一候補と距離の境界があれば，方向と見かけの大きさを保ったまま，境界の0.75倍と1.40倍の位置へ二端点を作れる．どちらの変換も画像を見ない．

したがって，この設定で「連続区間を直接返すhead」と「二端点だけを返すhead」を学習比較しても，前者だけが持つ出力機能は検証できない．差が出るとしても，parameterization，regularization，optimizationの差である．この理由から，予定していたVGGT backbone上のhead学習とABCI実験は実施しなかった．

解析的な変換を実装した既知解実験は二回行ったが，どちらもrendererのRGB検査が事前上限を越えた．256場面すべてで二つの変換が成功したという診断値は残っているが，計測器の検査が不合格であるため，経験的な成功結果としては扱わない．このIssueで残す結論は，明示した球の設定における解析的な還元だけである．

## E2E 3Dとどのようにつながるか

VGGTは複数のRGB画像からcamera，depth map，point map，3D trackなどを一回のfeed-forward推論で出す．これらは場面について一つの具体的な3D解を表す．

少数画像では，画像に一致する3D解が一つに定まらないことがある．そのときmodelが一つの解だけを返すと，学習時のpriorによって一候補を選ぶか，曖昧さをconfidenceへ押し込む必要がある．ここで検討したmethod上の変更は，曖昧さを一つの値へ潰さず，問いへの答えが異なる複数の3D候補を明示的に出力することである．

今回の問いは，この出力変更が本当に新しい機能を加えるか，それとも通常の出力から決定的に作れる表現を増やしただけか，というものである．学習前にこの区別がつけば，model比較が表現力を測るのか，単なる学習上の偏りを測るのかを混同せずに済む．

## どのような曖昧さを作ったか

一つの対象物体を球とし，カメラ中心からの距離と球の半径を同じ倍率で変える．カメラ中心を変えずに向きだけを変えて撮影すると，球が占める画角と表面の向きは変わらない．そのため，近くにある小さい球と，遠くにある大きい球は，同じ画像を作る．

距離の境界より近い候補は中心距離を境界の0.75倍，遠い候補は1.40倍とした．二候補は距離の問いへ反対に答えるが，4枚の初期画像は同じ光学中心から撮影するため区別できない．

![純回転で残る距離の曖昧さと解析的な還元](https://github.com/KohsukeIde/e2e-3d-notes/blob/main/figures/counterworld_geometry_and_reduction.png?raw=1)

*図1．左は，中心距離と半径を同じ倍率で変えた二つの球が，同じ視線の範囲へ投影されることを示す．右は，二端点から連続区間を作る変換と，一候補から二端点を作る変換である．どちらも3D候補が与えられた後は画像を使わない．*

同じ場面を横へ移動したカメラから見ると，視差によって二候補の投影位置が分かれる．この追加画像は，近い候補と遠い候補のどちらが正しいかを判別できる既知の証拠になる．

![純回転画像と横移動画像における二候補](https://github.com/KohsukeIde/e2e-3d-notes/blob/main/figures/counterworld_viewpoint_example.png?raw=1)

*図2．上段では光学中心が同じであるため，近い候補と遠い候補の投影が同じになる．下段ではカメラを横へ移動したため，紫の対象物体に視差が生じる．黄緑の球は位置を固定した物体である．この図は問題設定の可視化であり，数値実験の成功証拠ではない．*

## 仮説

実験前には二つの説明があった．

1. **連続区間が必要である．** 二つの候補を独立に出すだけでは，両者が同じ座標系にあり，間の全候補も画像と幾何を満たすことを保証できない．共有する3Dと変形方向を直接出す必要がある．
2. **二端点で十分である．** 近い候補と遠い候補が同じ正の放射方向上にあり，中心距離と半径が比例していれば，その間は解析的に復元できる．

自明でなかったのは，単に二つの数値を補間できるかではない．区間の途中で球が別の物体へ衝突せず，カメラの表示範囲から外れず，初期画像との一致も保たれる必要がある．今回は，この全区間の条件も連続な画像samplingではなく，距離の端点と衝突条件の二次式から解析的に判定した．

## 解析的な還元

### 二端点から連続区間を作る

二端点で，対象物体の中心方向，半径と中心距離の比，色が同じであることを確認する．そのうえで，中心位置と半径を同じ割合で線形補間する．補間中も中心距離と半径の比が変わらないため，共有した光学中心から見た投影は保たれる．

区間全体について，次を解析的に確認する．

- 対象物体の距離と半径が正である．
- near planeとfar planeから必要な距離を保つ．
- 位置を固定した別の球と衝突しない．
- 二つの球の投影が重ならない．
- 4枚の初期画像で対象物体が画像境界から必要な余白を保つ．

65点のrenderは実装上の退行を検出する診断にだけ使った．連続区間全体が有効であるという根拠は，上の解析条件である．

### 一候補から二端点を作る

区間内の一候補から，対象物体の中心方向，半径と中心距離の比，色を取り出す．距離の境界を受け取り，中心距離を境界の0.75倍と1.40倍へ置き，半径も同じ割合で変える．入力が近い端点，遠い端点，中央の候補のどれであっても，同じ二端点が得られる．

この変換にも，入力画像，画像feature，正解label，最適化は不要である．

## 数値実験では何を確認しようとしたか

解析式が正しくても，実装したrenderer，場面生成，区間判定，追加画像による候補選択に誤りがあれば，既知解の上でも処理は失敗する．そこで，答えを事前に構成できる合成場面だけを用い，二つの還元と計測器を同時に検査した．

| 項目 | 設定 |
|---|---|
| model | 学習modelは使わない．解析的な変換とvalidatorだけを使う |
| dataset | 球二個，固定背景，固定照明から生成した合成場面 |
| 初期画像 | 同じ光学中心から向きだけを変えた4枚 |
| 判別用画像 | カメラを距離の境界の0.25倍だけ横へ移動した1枚 |
| 画像 | 128×128，linear RGB，科学判定はfloat64 |
| 距離の二端点 | 境界の0.75倍と1.40倍 |
| 場面数 | 計測器の事前検査64場面，還元の診断256場面 |
| 区間検査 | 全区間の解析証明と，端点を含む65点の数値診断 |
| renderer検査 | 全画素の物体IDと交点距離，幾何から選んだ点の高精度再計算 |
| 実行環境 | CPUのみ．学習，追加最適化，ABCIは使わない |

計測器の事前検査では，64場面のそれぞれについて，6種類のカメラと近い・遠い二端点を組み合わせた768比較を行った．一つでも事前上限を越えれば，256場面の診断値を解釈しないと先に決めた．

## 結果

### Q1．連続な3D候補をmodelが直接出力する必要はあったか

**A．今回の球の設定では必要なかった．二端点と連続区間は解析的に相互変換できた．**

二端点から区間を作る処理も，一候補から二端点を作る処理も，画像を見ずに実行できる．したがって，連続区間を返すheadは，二端点を返すheadより多くの候補を表現できるわけではない．

この答えは，球の中心と半径を同じ倍率で変える設定に限定される．自然場面にある遮蔽，非剛体変形，複数物体の独立な移動，互いに離れた複数の解については答えていない．

### Q2．実際に実験は行ったのか

**A．合成場面による既知解実験は二回行ったが，VGGTの学習や推論は行っていない．**

最初の実行では，768 renderer比較のうち4比較，64場面のうち2場面でRGB誤差が事前上限を越えた．この結果を有効扱いせず，上限も広げなかった．代わりに，入力幾何だけから検査点を選び，256-bitで再計算し，512-bitの再計算と照合する独立検査を追加した．

計測器を作り直し，新しい64＋256場面で二回目を実行した．二回目もRGB検査に通らなかった．二回の失敗数は，場面集合と検査方法が異なるため，性能の増減として比較しない．

### Q3．二回目の実行は，具体的にどこで不合格になったか

**A．物体ID，交点距離，検査点の網羅，高精度計算の安定性は通ったが，768比較中16比較のRGB誤差が上限を越えた．**

16比較は8場面から生じた．交点距離の最大誤差は2.31×10⁻¹²で，上限1.00×10⁻¹¹以内だった．一方，RGBの最大誤差は3.28×10⁻¹²で，上限1.00×10⁻¹²を越えた．256-bitと512-bitによる高精度参照の最大差は1.72×10⁻⁷³であり，高精度参照自体の不安定さでは説明できない．

8場面では，近い端点と遠い端点の同じカメラが対になって失敗した．最大誤差はすべて，距離を問う対象物体ではなく，位置を固定した球の輪郭付近にあった．したがって，観測されたRGB超過は二端点の構成や候補選択の違いではなく，球の輪郭に近い視線と64-bit浮動小数rendererの数値誤差へ局在している．この誤差位置の分析も，事前上限を広げて実験を有効扱いする理由には使わない．

![二回目の実行における計測器の事前検査](https://github.com/KohsukeIde/e2e-3d-notes/blob/main/figures/counterworld_measurement_gate.png?raw=1)

*図3．左は必須とした768比較の内訳である．752比較はRGB上限内だったが，全比較を要求したため16比較の超過で実験全体を無効とした．右は，各検査を通った比較数である．*

これは解析的な還元が反例で壊れたという結果ではない．binary64で実装した二つのrendererが，高精度参照に対して事前に要求したRGB誤差内へ全比較で収まらなかったという計測上の失敗である．観測後に上限を広げたり，同じ問いで三回目を実行したりはしない．

### Q4．256場面すべてで変換が成功したなら，還元は実験でも確認できたのではないか

**A．確認できたとは扱わない．計測器の事前検査が不合格だったため，256 / 256は診断値にとどまる．**

256場面では，二端点から区間を作る処理，一候補から二端点を作る処理，横移動画像による正しい候補の選択，全区間の解析条件，65点の数値診断がすべて成功した．しかし，これらを数える前提だった計測器が不合格である．この値から経験的な成功率や一般化性能を主張しない．

### Q5．なぜVGGTで二つのheadを比較しなかったのか

**A．その比較では，連続区間だけが持つ機能を検証できないと学習前に分かったからである．**

二端点headの出力から連続区間を決定的に作れるため，連続区間headが勝っても，区間を出せること自体の優位にはならない．同じbackbone，parameter数，学習量を揃えても，残る差は出力の条件付けやregularizationである．それは別のresearch questionであり，今回の「どちらが機能的に強いか」という問いへの実験ではない．

## この結果から言えること

- 同じ正の放射方向上で，球の中心距離と半径だけが比例する設定では，二端点から端点間の全候補を解析的に作れる．
- 同じ設定では，任意の一候補と距離の境界から，反対回答を持つ固定倍率の二端点を解析的に作れる．
- したがって，この設定における連続区間は，二端点より機能的に強いmodel出力ではない．
- 既知解実験の数値結果は，計測器の事前検査に通らなかったため，経験的な裏付けとして使えない．
- VGGT上のhead学習は未実施であり，VGGTの性能についての結果はない．

## 言えないこと

- 自然画像からmodelが正しい二端点を予測できるかは分からない．
- 球以外の形状，遮蔽を伴う場面，非剛体場面，複数物体が別々に動く場面へ還元できるとは限らない．
- 互いにつながらない複数解や，途中が無効になる二端点を一つの線分で表せるとは限らない．
- 連続区間を直接出すことが学習しやすさ，calibration，sample efficiencyを改善しないとは言えない．今回は機能的な表現力だけを問うた．
- 256場面の診断値から，実装成功率や一般化性能は言えない．
- RGB検査の失敗は解析式の反証ではなく，解析式の成立はrenderer実装の成功証拠でもない．

## このテーマの扱い

この球の設定で連続区間headと二端点headを比較する計画は終了する．同じ比較を大きなmodelや実画像へ移しても，解析的な同値性は変わらない．次に曖昧さをmodel出力として扱うなら，最も強い通常出力から決定的に復元できない対象を先に定義する必要がある．
